# Release critique — worker `0.65.6` (Claude Code guide host)

- Execution: bounded fresh-eye subagents (2 implementation angles + 1 release
  angle); the first release-angle spawn went idle without delivering a report and
  was re-run synchronously rather than assumed
- Fresh-Eye Satisfaction: parent-delegated
- Reviewed Input Identity: commits `f30efb7`, `9d44ba9` on `main`; the release
  angle also reviewed the drafted `0.65.6` CHANGELOG entry before any bump
- Reviewer tier requested: high-leverage; host exposed model override only
- Boundary: read-only reviewers (no Bash/Edit/Write/Agent); every load-bearing
  finding below was re-verified in the source by the parent before disposition

## Change

Add `ceal guide register claude` beside `register codex` as a declared agent
host, keep `ceal.guide.v1` readable by a Codex-only consumer, and publish it as
worker `0.65.6` (`ceal-v0.65.6`). Lock-in event: pushing the tag, which is what
moves the mutable `stable` pointer for every installed worker.

## Capability at Stake

An operator adopting Ceal from Claude Code can link the same update-safe signed
guide their Codex colleague links, and an agent reading `ceal.guide.v1` can tell
which hosts are registered without inferring it from a single-host projection.

## Angles

1. Output-contract compatibility and boundary honesty of `ceal.guide.v1`
2. Local-write safety of per-host registration (paths, overrides, occupants)
3. Release decision: bump level, tag/version coupling, missed version sites,
   CHANGELOG honesty, pipeline and installed-user risk

## Findings and Disposition

### Fixed before the release commit

- **Implementation, applied in `9d44ba9`** (7 findings): guide-unavailable
  answered `agent: codex` to a `register claude` question; a relative or
  colon-list host root was joined instead of refused; `hosts` silently dropped an
  unresolved host and mislabeled a refusing path as `staged`; the default
  projection followed resolvability so a Codex-only reader could be handed
  Claude's path; the route token reached the store as an unchecked cast; the
  observer rendered no per-host list; the probe guard left `XDG_RUNTIME_DIR`
  inherited, keeping an operator-real admin Gateway socket reachable from a
  `control_write` probe.
- **CHANGELOG bullet 3 asserted a bug in a code path that never existed**
  (blocker). The draft said a relative or colon-separated
  `CLAUDE_CONFIG_DIR`/`CODEX_HOME` "was previously joined"; `CLAUDE_CONFIG_DIR`
  was first read in this slice, so only `CODEX_HOME` had that behavior. The same
  sentence called the colon case a working-directory write, but
  `join("/a:/b", …)` is absolute — it would have created a literal `a:` directory.
  Re-verified in source and rewritten.
- **Three CHANGELOG omissions** (worth-fixing): `hosts` is emitted from
  `guide register` as well as `guide status`; `ceal observe` changed its
  data-source disclosure string; a relative `CODEX_HOME` now flips
  `ceal guide status` from exit 0 to exit 3 with `registration_failed`, which is
  the correct answer but is a behavior break for an existing script. The
  "one declaration per host" claim was also scoped to the guide surface, since
  `agent-audit.ts` still ignores both overrides.
- **`npm run check` does not gate `package-lock.json`** (worth-fixing, highest
  pipeline risk). CI runs `npm ci --ignore-scripts`
  (`.github/workflows/ceal-release.yml:68`), which fails on a stale lock; the repo
  has burned a tag this way before (`CHANGELOG.md:50-55`, the `0.65.2` → `0.65.3`
  replacement). Added `npm ci` to the pre-tag sequence instead of trusting
  `npm run check` alone.

### Accepted as-is

- **`0.65.6` as a patch** rather than the policy-default minor for a new
  operator command. Nothing in the install/update path reads the minor digit:
  `install-ceal.sh:146`, `stable-update.ts:145`, and the stable-pointer guard at
  `ceal-release.yml:315` all compare componentwise, `release-contract.json:5`
  freezes `release_version` at `0.65.0` while worker/client move independently,
  and repo precedent already shipped whole platforms (`0.65.4`) and new output
  surfaces (`0.65.5`) as patches. The capability signal lives in the CHANGELOG.
- **The pipeline fails closed on every version miss** that was checkable: the
  tag-derived version is compared against the built artifact
  (`build-worker-release-assets.mjs:53`), the two package manifests must agree
  (`build-worker-native-artifact.mjs:260`), the built binary's own
  `ceal version` must match (`:195`), each manifest is grepped before signing
  (`ceal-release.yml:210`), and the installer re-derives the expected version
  document (`install-ceal.sh:235`). A miss costs the tag, never a partial
  publish.
- **No pin needs to move**: guide `sha256` pins only move when
  `skills/*/SKILL.md` changes (it did not — the signed guide names no agent
  host), protocol wire `1.3.0` and the `gateway-handoff-v0.65.0` archive are
  independent of the worker version, and the offline consumer cache excludes
  `@corca-ai/`.
- **Four-platform all-or-nothing** assembly: one flaky runner burns the tag with
  zero user impact. Proven at `0.65.5`; no action.

### Carried as an open risk, not fixed here

- **The readback proves a symlink, not adoption.** `register claude` +
  `guide status` prove a link at `<CLAUDE_CONFIG_DIR|~/.claude>/skills/ceal-guide`
  resolving into the release generation. They do not prove Claude Code loads a
  skill through a symlinked directory. Until a Claude Code session enumerates
  `ceal-guide`, the route's success message is honest about the link and silent
  about adoption — the same shape of gap this slice fixed elsewhere. Recorded in
  the release ledger and in `docs/handoff.md` as the first thing to verify.
- **Colon-list `CLAUDE_CONFIG_DIR`** is refused as "not one absolute path" on the
  unverified assumption that Claude Code does not accept a colon-separated list.
  If it does, the refusal is unnecessary and the route should resolve the first
  entry.
- **`agent-audit.ts` ignores `CLAUDE_CONFIG_DIR`/`CODEX_HOME`** while the guide
  surface honors them. One binary, two conventions; filed as a follow-up in the
  handoff rather than widened into this release.

## Verdict

Release after the two pre-tag edits (CHANGELOG wording, lockfile proof). The
reviewer's own line: `RELEASE VERDICT: no-go` until those land; both were
pre-tag edits and both are applied in the release commit.
