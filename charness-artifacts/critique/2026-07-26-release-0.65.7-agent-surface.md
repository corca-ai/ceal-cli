## Change

Resolve `corca-ai/ceal-cli#2`, `#3`, `#4` — the failure-report contract an agent
consumes — and publish them as worker `0.65.7`. Lock-in event: the tag, which

## Verdict as received

`RELEASE VERDICT: no-go`, on two blockers. Both were about the release
contradicting its own headline, and both were correct.

## Findings and Disposition

### Blockers, fixed before the tag

- **`ceal capabilities` without a session emitted `ok: false`, no `error`
  object, and exit code 0.** The most-hit failure state on that surface — fresh
  install, logged out — was a failure that looked like success, published by the
  release whose stated point is that one field can be trusted. A consumer
  adopting this release's own rule (`if (!doc.ok) handle(doc.error.kind)`) would
  throw on the most common case. Now carries
  `error.kind: client_session_unavailable` and exits 3.
- **The changelog claimed "every result document carries `ok`" while eight
  schemas did not** (`guide`, `version`, `commands`, `update`, `observe`,
  `client_session`, `session_enrollment`, `session_logout`). Publishing the claim
  is worse than publishing the partial rollout, because the claim is what a
  consumer codes against. `ok` now covers every command, and the definition was
  sharpened in the process: it means *this command answered what it was asked*,
  not *the state is good*, so `session: unconfigured` is `ok: true`.

### Worth-fixing, also fixed

- **Host detection picked by table order when two hosts' markers were present.**
  A nested agent always produces that, since it inherits the outer host's
  environment; the advisory would then name a host that is not running —
  `#4` reinstated one level down. Ambiguity now degrades to undetected.
- **The effect lookup behind the replay caution ignored the cache key and TTL**
  while the catalog path gates the same single-file cache on both. A stale or
  cross-instance entry could call a write a read and suppress the caution for a
  call with an unknown outcome — and cross-instance confusion is this release's
  own documented reality (`#3`).
- **`error: { code, ... }` shorthand slipped past the structural gate**, so an
  enrollment rejection still published `code` without `kind`. Gate tightened,
  case fixed.
- **The signed guide did not teach the new predicate.** It ships inside the
  release, so a later guide-only correction needs another release; it rides this
  tag.

### Accepted as-is

- **Additive fields** (`gateway:`, `kind` beside `code`, `agent_source`,
  `agent_guide`) are key additions. The one cross-repo consumer found is
  field-selective; the receipt spool projects by allowlist and ignores them.
- **`agent`'s meaning change** in `ceal.guide.v1` — from first declared host to
  detected running host — is semantic, not additive, and is the point of `#4`.
  Two readers regress and are recorded rather than silently broken: a recorded
  capability-matrix procedure in the Gateway repo that says "run `guide register
  codex`", and the legacy compatibility copy of `agent-guide.ts` in that repo,
  which still types `agent` as the literal `"codex"` and must be resynced from
  the owner per the extraction ledger, never edited independently.

## Residual Risks

- `ceal version` gained a line. Our own installer compared that document
  byte-for-byte and broke; it is fixed here, but any external golden comparison
  of `ceal version` breaks the same way. Called out in the changelog.
- `capabilities` moving from exit 0 to exit 3 with no session is a deliberate
  behavior change for anyone scripting that surface on a fresh install.
- `code` remains beside `kind` on the surfaces that published it first; removing
  it is a later release's decision.
