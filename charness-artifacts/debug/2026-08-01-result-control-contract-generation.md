# Result Control Contract Generation Debug
Date: 2026-08-01

## Problem

Changing the private worker control session to the released result-bearing v2
grammar made `npm run build:worker` stop with `handoff_generation_failed`.

## Correct Behavior

Given the Gateway protocol handoff already exports the v2 grammar, when the
worker elects that grammar, then the checked control contract, generator,
generated source, runtime decoder, and release-manifest input must name the
same v2 pair; an incomplete or mixed pair must refuse to build.

## Observed Facts

- The contract was changed to `ceal.leased_consumer_result_control_{request,response}.v2`.
- `scripts/generate-leased-consumer-handoff-runtime.mjs#readControlSessionContract`
  still exact-matches only the v1 pair and emitted `handoff_generation_failed`.
- Direct package builds used stale generated contract bytes and therefore
  failed the runtime's embedded-contract assertion.
- The vendored signed protocol handoff `v0.71.8` exports the v2 decoders.

## Reproduction

- Change only the two `agent_ipc` schema strings to v2, then run
  `npm run build:worker` → `{\"ok\":false,\"error_code\":\"handoff_generation_failed\"}`.

## Candidate Causes

- The generator intentionally allows only the prior v1 control contract.
- The vendored protocol lacks the v2 decoder exports.
- The generated TypeScript mirror was stale after a valid contract change.

## Hypothesis

- The exact v1 generator guard is the only blocking invariant; updating its
  paired contract expectation and regenerating will allow v2 while preserving
  refusal for mixed or unknown schemas. | disconfirmer: a v2-aware generator
  still fails before TypeScript build or accepts a mixed pair.

## Verification

- confirmed — static read shows both contract values are v2 while the
  generator alone requires both v1; the v2 symbols compile from the vendored
  protocol after the generated mirror is refreshed.

## Root Cause

The prior v1 carrier was intentionally closed under a generator validation
rule. The new result-control carrier changes a release-bound grammar and must
move that generator rule with the worker runtime rather than treating generated
source as an editable compatibility copy.

## Invariant Proof

- Invariant: when the checked private control contract elects a grammar, the
  generator and the installed worker must emit and consume that exact grammar
  before release packaging can claim a valid carrier.
- Producer Proof: `readControlSessionContract` rejects the checked v2 pair.
- Final-Consumer Proof: `assertEmbeddedControlSessionContract` rejects stale
  generated v1 bytes before any child session opens.
- Interface-Shape Sibling Scan: generated carrier-contract and handoff mirrors
  use the same checked-input → generated-source → runtime-assert pattern.
- Non-Claims: no Gateway socket, credential, Agent process, or provider path
  was started.

## Detection Gap
